The `[download]` section in `server/config.toml` controls how the recorder pulls a stream.

```toml
[download]
max_concurrent          = 5
segment_concurrency     = 4
network_attempts        = 5
server_error_attempts   = 5
cdn_lag_attempts        = 3
auth_refresh_attempts   = 2
max_gap_ratio           = 0.01
strict                  = false
enable_av1              = false
disable_hevc            = false
max_restart_gap_seconds = 120
```

## Concurrency

| Key                   | What it does |
| --------------------- | ------------ |
| `max_concurrent`      | Cap on parallel recordings across the whole server. |
| `segment_concurrency` | Parallel HLS segment fetches inside a single recording. |

Bump `max_concurrent` if you record many channels at once and have the disk + network for it. Bump `segment_concurrency` only if a single recording is bottlenecked on download throughput.

## Quality

Choose quality when starting a recording or editing its schedule in the dashboard. Each recording saves its own choice; scheduled recordings use the schedule's saved choice.

| Dashboard choice | API `quality` | Maximum video height |
| ---------------- | ------------- | -------------------- |
| Best available | `BEST` | Highest eligible rendition offered by the channel. |
| 1440p | `1440` | 1440p |
| High | `HIGH` | 1080p |
| Medium | `MEDIUM` | 720p |
| Low | `LOW` | 480p |

The recorder chooses the highest available rendition at or below the limit after applying codec settings. A channel offering 1440p and 720p records at 1440p with **1440p** or **Best available**, and at 720p with **High**. It never raises a selected limit to reach a higher rendition. At equal height it prefers HEVC, then enabled AV1, then H.264, followed by the higher frame rate. If no eligible video rendition fits, the recording fails.

New recording forms default to **High**. The API also uses `HIGH` when a manual recording request omits `quality`; schedule requests must supply a quality. Choose **Audio only** (API `recording_type: "audio"`) separately to record the audio rendition; video quality and codec settings do not apply to audio.

The retired `[download].preferred_quality` config key had no effect on recording selection. Existing config files may retain it: the server ignores it and logs a deprecation warning. Use the recording or schedule quality control instead.

## Codecs

| Key            | Default | Effect |
| -------------- | ------- | ------ |
| `enable_av1`   | `false` | Allow AV1 variants when the channel ladder includes them. |
| `disable_hevc` | `false` | Refuse HEVC variants even when offered. |

HEVC and AV1 are gated behind authenticated playback on some channels. Set `TWITCH_SERVICE_ACCOUNT_REFRESH_TOKEN` in `server/.env` to a Twitch refresh token if you want those variants on those channels.

## Retries

| Key                     | When it applies |
| ----------------------- | --------------- |
| `network_attempts`      | Generic network failures (TCP reset, DNS, etc.). |
| `server_error_attempts` | Twitch returned 5xx for a segment. |
| `cdn_lag_attempts`      | Segment isn't on the CDN yet. |
| `auth_refresh_attempts` | Playback token expired and needs refresh. |

Retry budgets are per-segment, not per-recording. The recorder gives up on a segment after exhausting its budget; it does not give up on the recording.

## Gaps and resumes

| Key                       | Default | Effect |
| ------------------------- | ------- | ------ |
| `max_gap_ratio`           | `0.01`  | Tolerated fraction of dropped segments before the recording is marked incomplete. |
| `strict`                  | `false` | If `true`, any gap fails the recording. If `false`, gaps under the ratio are auto-healed. |
| `max_restart_gap_seconds` | `120`   | If the stream drops and comes back within this window, the recorder appends to the same VOD instead of starting a new one. |

<Aside type="tip" title="Why the recording shows 'incomplete'">
  Recordings whose realised duration is meaningfully shorter than expected (i.e. exceed `max_gap_ratio`) get an "incomplete" badge in the dashboard. The video still plays — the badge is a heads-up, not an error.
</Aside>
